# Telegram: бот и авторизация

## 1. Создание бота

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Задайте имя и username (должен заканчиваться на `bot`).
3. Сохраните токен вида `123456789:AA...` — это `TELEGRAM_BOT_TOKEN`.
4. Username без `@` положите в `TELEGRAM_BOT_USERNAME`.

Рекомендуемые настройки у BotFather:

```
/setdescription   — Корпоративная доска задач. Уведомления по вашим задачам и вход в веб-интерфейс.
/setabouttext     — Задачи, дедлайны и обсуждения вашей команды.
/setuserpic       — загрузите логотип
/setprivacy       — Enable (боту не нужны чужие сообщения в группах)
```

Команды бот регистрирует сам при запуске — вручную `/setcommands` делать не нужно.

> Для разработки заведите **отдельного** бота. Один токен на два окружения
> означает, что вебхук и long polling будут отбирать обновления друг у друга.

## 2. Режимы работы

| Режим | Когда | Настройки |
|---|---|---|
| `polling` | Разработка на localhost | `BOT_MODE=polling` |
| `webhook` | Продакшен | `BOT_MODE=webhook`, `BOT_WEBHOOK_URL=https://<домен>` |

В режиме вебхука бот слушает `/telegram/<TELEGRAM_WEBHOOK_SECRET>`;
Caddy проксирует туда запросы. Секрет участвует и в пути, и в заголовке
`X-Telegram-Bot-Api-Secret-Token` — оба проверяются.

Проверить состояние:

```bash
curl "https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo"
```

Снять вебхук (например, чтобы временно перейти на polling):

```bash
curl "https://api.telegram.org/bot<ТОКЕН>/deleteWebhook"
```

## 3. Вход в веб-интерфейс

```
Браузер                     Сервер                    Telegram
   │  «Войти через Telegram»   │                          │
   ├──────────────────────────►│                          │
   │   код + ссылка t.me/...   │                          │
   │◄──────────────────────────┤                          │
   │                                                      │
   │  открывает ссылку ────────────────────────────────►  │
   │                           │   /start <код>           │
   │                           │◄─────────────────────────┤
   │                           │  бот знает telegram_id   │
   │   опрос статуса           │                          │
   ├──────────────────────────►│  APPROVED                │
   │   обмен кода на токены    │                          │
   ├──────────────────────────►│                          │
   │   access + refresh        │                          │
   │◄──────────────────────────┤                          │
```

Код живёт 2 минуты и одноразовый. Подробности защиты — [SECURITY.md](./SECURITY.md).

Побочный и очень полезный эффект: сразу после входа пользователь уже находится
в чате с ботом, поэтому уведомления работают с первой минуты — не нужно
отдельно уговаривать людей «не забудьте запустить бота».

## 4. Команды бота

| Команда | Что делает |
|---|---|
| `/start` | Привязка аккаунта, подтверждение входа |
| `/tasks` | Мои активные задачи |
| `/today` | Что горит сегодня |
| `/testing` | Задачи, где я тестировщик |
| `/me` | Профиль и статус привязки |
| `/settings` | Настройка уведомлений кнопками |
| `/mute` · `/unmute` | Быстро выключить и включить уведомления |
| `/logout` | Выйти из веба на всех устройствах |
| `/help` | Справка |

## 5. Действия прямо из чата

**Ответ на уведомление.** Обычный ответ (reply) на сообщение бота превращается
в комментарий к задаче. Автор ответа автоматически становится контрибьютором.

**Кнопки под уведомлением** зависят от события:
- назначили задачу → «▶️ В работу», «💬 Ответить»;
- задачу вернули или поставили на паузу → «▶️ В работу», «💬 Ответить»;
- новый комментарий или упоминание → «💬 Ответить»;
- назначили тестировщиком → «✅ Принято», «💬 Ответить».

**Обязательная причина работает и здесь.** Если быстрое действие требует
объяснения (возврат назад, пауза), бот попросит написать причину ответом
на сообщение — и только потом применит изменение. Правила одинаковы
в вебе и в Telegram, потому что и то и другое идёт через один и тот же API.

## 6. Уведомления

| Событие | Кому |
|---|---|
| Назначили исполнителем | новому исполнителю и снятому |
| Назначили тестировщиком | тестировщику |
| Смена статуса | всем участникам задачи |
| Возврат назад / пауза (с причиной) | всем участникам, с текстом причины |
| Изменён дедлайн | всем участникам |
| Новый комментарий | всем, кроме автора комментария |
| Упоминание `@` | упомянутому — всегда |
| Приложен файл | участникам |
| Скоро дедлайн (24 ч, 2 ч) | исполнителю |
| Просрочено | исполнителю и автору |
| Добавили на доску | приглашённому |
| Утренняя сводка | всем, у кого есть активные задачи |

**Против спама.** Уведомления по одной задаче для одного человека склеиваются
в одно сообщение (окно 12 секунд). Заголовком становится самое важное событие,
остальные идут списком ниже.

**Тихие часы.** Обычные уведомления не приходят ночью. Упоминания, назначения
на вас и события безопасности приходят всегда — их пропускать нельзя.

**Блокировка бота.** Если пользователь заблокировал бота, Telegram отвечает 403;
мы помечаем это в базе и прекращаем попытки. Разблокировка обнаруживается
автоматически по событию `my_chat_member`.

## 7. Mini App (необязательно)

Доску можно открывать прямо внутри Telegram:

1. У BotFather: `/newapp` → выберите бота → укажите `https://<домен>`.
2. Фронтенд определит `window.Telegram.WebApp` и авторизуется через
   `POST /api/auth/telegram/mini-app` с `initData`.

Проверка подписи `initData` уже реализована на сервере
(`verifyMiniAppInitData`), включая защиту от повторного использования.
