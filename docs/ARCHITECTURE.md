# Архитектура

## Общая картина

```
┌──────────┐   HTTPS    ┌───────────────┐
│ Браузер  │ ─────────► │     Caddy     │  TLS, статика фронта, обратный прокси
│  (SPA)   │ ◄────────  └───────┬───────┘
└──────────┘   WebSocket        │
                                ├──► /api/*      ─► API (Fastify)
                                ├──► /socket.io  ─► API (Socket.IO)
                                └──► /telegram/* ─► Бот (webhook)

┌───────────────────────────────────────────────────────────┐
│ API (один процесс)                                        │
│   HTTP-роуты · Socket.IO · воркеры BullMQ                 │
└───────┬───────────────────────────┬───────────────────────┘
        │                           │
   PostgreSQL                     Redis
   (данные)          (кеш, presence, очереди, pub/sub)
                                    ▲
                                    │
                              Бот (grammY) ── служебный API ──► API
```

Всё живёт на одном VPS и умещается в 4 ГБ памяти. При росте нагрузки
процессы разносятся без изменения кода: события ходят через Redis,
очереди распределённые, Socket.IO работает с Redis-адаптером.

---

## Почему так

### Один домен для фронта и API
Фронт и API отдаются с одного домена. Это позволяет:
- держать refresh-токен в cookie с `SameSite=Strict` (жёсткая защита от CSRF);
- не платить за preflight-запросы;
- не думать о `COOKIE_DOMAIN` и кросс-доменных куках.

### Бот — тонкий клиент
Бот не пишет в базу напрямую. Он ходит в `/api/internal/*` с общим секретом.
Благодаря этому правила (права, обязательные причины, участники, уведомления)
существуют в одном экземпляре и не расходятся между вебом и Telegram.

Исходящие сообщения при этом отправляет **API**, а не бот: перезапуск бота
не влияет на очередь уведомлений и наоборот.

### Общий пакет контрактов
`packages/shared` содержит enum'ы, zod-схемы, матрицу прав и бизнес-правила.
И сервер, и клиент импортируют один и тот же код: форма запроса,
подсветка дедлайна и решение «нужна ли причина» считаются одинаково.

## Слои API

```
routes/    → разбор запроса (zod), вызов сервиса, форматирование ответа
service/   → бизнес-логика и транзакции
lib/       → инфраструктура: prisma, redis, rbac, файлы, токены, санитайзер
services/  → сквозные вещи: уведомления, активность, участники
queue/     → очереди и воркеры
realtime/  → Socket.IO и мост событий
```

Правило: роуты не знают о Prisma, сервисы не знают о HTTP.

### Транзакционность

Любая операция, меняющая задачу, выполняется одной транзакцией:
обновление полей, синхронизация участников, системный комментарий с причиной
и запись в историю. Полусохранённого состояния возникнуть не может.

Уведомления отправляются **после** транзакции: их доставка не должна
блокировать пользователя и не должна откатывать бизнес-операцию.

## Модель данных

Полная схема — `apps/api/prisma/schema.prisma`. Ключевые решения:

**Порядок карточек — дробный индекс (строка)**
Перенос карточки = `UPDATE` одной строки. Никакой переиндексации колонки,
никаких гонок при одновременном перетаскивании двумя людьми.

**Денормализованные счётчики на задаче**
`commentCount`, `attachmentCount`, `checklistTotal/Done`, `blockedByCount`
обновляются в той же транзакции. Доска с сотнями задач грузится одним запросом
без агрегатов. Ночная джоба сверяет счётчики — на случай сбоев.

**Ключ задачи денормализован**
`OPS-128` хранится в самой задаче и уникален глобально. По нему работают поиск,
ссылки из Telegram и упоминания в тексте. Ключ доски после создания не меняется —
иначе пришлось бы переписывать все ссылки.

**Мягкое удаление там, где важна история**
Комментарии и задачи архивируются, а не стираются. Жёсткое удаление есть,
но требует ввода ключа задачи руками.

**Участники задачи — отдельная таблица с ролями**
Один человек может быть одновременно автором и исполнителем. Тот, кто написал
комментарий, автоматически становится контрибьютором: дальше он в курсе.
Отписаться можно вручную — это флаг `muted`, а не удаление роли.

## Реалтайм

Комнаты Socket.IO:
- `user:<id>` — личные уведомления;
- `board:<id>` — изменения задач и присутствие;
- `task:<id>` — комментарии и индикатор «печатает».

Подписка на доску проверяет членство на сервере — подключиться к чужой доске нельзя.

События публикуются не напрямую, а через Redis (`realtime/bridge.ts`).
Поэтому воркер, живущий в другом процессе, может «достучаться» до клиента
тем же вызовом, что и HTTP-роут.

Клиент на событие не перерисовывает всё подряд: он инвалидирует конкретные
ключи React Query. Свои собственные изменения игнорируются — их уже применил
оптимистичный апдейт.

Что именно приходит по сокету:

| Где | Что обновляется живьём |
|---|---|
| Доска | Создание, перенос, изменение и удаление задач; состав участников; настройки |
| Открытая задача | Комментарии, реакции, вложения, поля, статус; закрытие при удалении |
| Обсуждение | Индикатор «печатает…» и новые реплики без перезагрузки |
| Присутствие | Кто сейчас на доске и кто открыл эту же задачу |
| Колокольчик | Новые уведомления и счётчик непрочитанных |
| Сессии | «Выйти на всех устройствах» разлогинивает вкладки сразу |

Новый комментарий кладётся в кеш прямо из события, а не вызывает перезапрос
всего обсуждения: одна реплика не должна стоить лишнего запроса и мигания
списка. Флаг «моя реакция» при этом пересчитывается на клиенте — сервер
считает его относительно того, кто реакцию поставил.

Если сокет отвалился (перезапуск сервера, спящий ноутбук), на доске
появляется отметка «обновления приостановлены». Молча устаревший интерфейс
опаснее честного признания, что связи нет.

## Очереди

| Очередь | Что делает |
|---|---|
| `telegram-delivery` | Отправка сообщений с ретраями, склейкой и лимитом темпа |
| `scheduler` | Напоминания о дедлайнах (24 ч / 2 ч / просрочка), утренняя сводка |
| `maintenance` | Ночная уборка: висящие файлы, просроченные коды, старые сессии, сверка счётчиков |

**Склейка уведомлений.** Джоба на пару «пользователь + задача» ставится
с задержкой 12 секунд и общим `jobId`. Пока она ждёт, новые события по той же
задаче накапливаются в базе и уходят одним сообщением. Без этого активное
обсуждение превращает бота в спамера, и его выключают.

## Фронтенд

- **React Query** — серверное состояние: кеш, оптимистичные апдейты, инвалидация.
- **Zustand** — локальное состояние интерфейса: фильтры, тема, свёрнутые колонки.
  Хранится в `localStorage`, поэтому переживает перезагрузку.
- **dnd-kit** — перетаскивание с поддержкой тача и клавиатуры.
  На мобильных — долгий тап (иначе доска не прокручивалась бы пальцем).
- **TipTap** — редактор описаний и комментариев. Для **просмотра** используется
  собственный рендерер JSON: в ленте комментариев их десятки, и поднимать
  ProseMirror на каждый — расточительно.

Код разделён по маршрутам (`React.lazy`): тяжёлые редактор и графики
не попадают в первый бандл.
