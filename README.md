# Kaif Board

Корпоративная доска задач с авторизацией через Telegram и ботом-уведомителем.
React + TypeScript, Fastify + PostgreSQL, self-hosted на своём VPS.

> Полный технический план проекта — в [PLAN.md](./PLAN.md).

---

## Что умеет

**Доски и задачи**
- Неограниченное число досок; создатель автоматически становится владельцем.
- Шесть фиксированных колонок: `Todo → On hold → In progress → QA → Ready to release → Done`.
- Задачи с форматированным описанием, исполнителем, тестировщиком, метками, приоритетом,
  типом, оценками, чек-листами, связями между задачами и вложениями.
- Дедлайны с наглядной подсветкой: просрочено, сегодня, меньше суток, скоро.
- Бэклог («банк задач») с массовыми операциями: назначить, проставить приоритет, отправить на доску.
- Меню быстрых действий на карточке (и по правой кнопке): взять в работу, сменить исполнителя,
  сдвинуть срок, переложить в колонку, дублировать, в архив — не открывая задачу.
- Дорожки (swimlanes) по исполнителю, приоритету или типу.
- Сохранённые фильтры — личные и общие для доски.
- Выгрузка задач в CSV с учётом текущих фильтров.

**Дисциплина процесса**
- Поставить задачу на паузу, вернуть её назад или перенести дедлайн **нельзя молча** —
  сервер требует письменного объяснения. Оно сохраняется в истории задачи и уходит участникам.
- Полный аудит: кто, что и когда изменил, с какого адреса.
- WIP-лимиты по колонкам, запрет закрывать заблокированные задачи, обязательный тестировщик для QA.

**Люди**
- Роли на доске: владелец, администратор, участник, наблюдатель. Глобальная роль суперадмина.
- Панель «Люди»: загрузка каждого, просрочки, кнопка «Создать задачу на него».
- Автоматические контрибьюторы: написал комментарий — стал участником задачи и получаешь уведомления.
- Реакции на комментарии: короткое «понял» не превращается в отдельное сообщение.

**Telegram**
- Вход по одноразовому коду через бота — без паролей и без привязки к домену.
- Уведомления о назначениях, комментариях, упоминаниях, возвратах и дедлайнах.
- Быстрые действия прямо из чата: взять в работу, ответить комментарием, сменить статус.
- Утренняя сводка, тихие часы, тонкая настройка типов уведомлений.

**Интерфейс**
- Реалтайм: карточки двигаются у всех сразу, видно, кто сейчас на доске и кто печатает.
- Мобильный режим: свайп между колонками, перетаскивание долгим тапом, bottom-sheet вместо модалок.
- Командная палитра `Cmd/Ctrl+K`, горячие клавиши (работают и на русской раскладке), справка по `?`.
- Тёмная тема, PWA с установкой на телефон, просмотр вложений в лайтбоксе.
- Черновики комментариев переживают перезагрузку страницы.
- Ключи задач в тексте (`OPS-12`) автоматически становятся ссылками.
- Аналитика: время цикла, поток задач, нагрузка людей, «узкие места».

## Быстрый старт (разработка)

Нужны **Node.js 22+**, **Docker** (для Postgres и Redis) и бот от [@BotFather](https://t.me/BotFather).

```bash
git clone <репозиторий> kaif-board && cd kaif-board
npm install

# Инфраструктура
docker compose up -d

# Конфигурация
cp .env.example .env
```

Минимум, что нужно поправить в `.env` для локального запуска:

```dotenv
NODE_ENV=development
APP_URL=http://localhost:5173
API_URL=http://localhost:4000
DATABASE_URL=postgresql://kaif:kaif@localhost:5432/kaif_board?schema=public
REDIS_URL=redis://127.0.0.1:6379
JWT_SECRET=<openssl rand -base64 48>
INTERNAL_API_SECRET=<openssl rand -base64 32>
TELEGRAM_BOT_TOKEN=<токен от BotFather>
TELEGRAM_BOT_USERNAME=<имя_бота_без_@>
SUPERADMIN_TELEGRAM_IDS=<ваш telegram id>
BOT_MODE=polling
STORAGE_DIR=./storage
TRUST_PROXY=false
```

Дальше:

```bash
npm run db:migrate      # применить миграции
npm run db:seed         # демонстрационные данные (необязательно)

npm run dev:api         # API + реалтайм + воркеры  → http://localhost:4000
npm run dev:bot         # Telegram-бот (long polling)
npm run dev:web         # интерфейс                → http://localhost:5173
```

Откройте `http://localhost:5173`, нажмите «Войти через Telegram» — бот подтвердит вход.

## Продакшен

Подробная инструкция: [docs/DEPLOYMENT.md](./docs/DEPLOYMENT.md).

Коротко — на чистом VPS с направленным на него доменом:

```bash
sudo bash deploy/setup-server.sh          # Docker, firewall, пользователь
su - kaif && cd /opt/kaif-board
cp .env.example .env && chmod 600 .env    # заполнить домен, секреты, токен бота
docker compose -f docker-compose.prod.yml up -d --build
```

Caddy сам получит TLS-сертификат, API применит миграции при старте,
бот зарегистрирует вебхук. Проверка: `curl -I https://<домен>/healthz`.

## Структура

```
kaif-list/
├─ packages/shared/   Общие типы, zod-схемы, матрица прав, бизнес-правила
├─ apps/api/          Fastify, Prisma, Socket.IO, очереди, воркеры
├─ apps/bot/          Telegram-бот (grammY)
├─ apps/web/          React + Vite
├─ deploy/            Dockerfile, Caddyfile, скрипты сервера и бэкапов
└─ docs/              Архитектура, безопасность, деплой, API, Telegram
```

`packages/shared` — единственный источник правды для контрактов: и API, и фронтенд
используют одни и те же zod-схемы и одну и ту же матрицу прав.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev:api` / `dev:bot` / `dev:web` | Запуск в режиме разработки |
| `npm run build` | Сборка всех пакетов |
| `npm run typecheck` | Проверка типов во всех воркспейсах |
| `npm test` | Тесты (права, правила, подписи Telegram, санитайзер) |
| `npm run db:migrate` | Применить миграции (dev) |
| `npm run db:deploy` | Применить миграции (прод) |
| `npm run db:seed` | Демонстрационные данные |
| `npm run db:studio` | Prisma Studio |
| `npm run infra:up` / `infra:down` | Postgres и Redis в Docker |
